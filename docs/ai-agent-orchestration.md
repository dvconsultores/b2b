# AI Agent Orchestration — Claude (Thinker) + DeepSeek (Executor)

> **Summary:** How this project configures Claude Code to plan, audit and test
> work while delegating bounded implementation tasks to DeepSeek through an MCP
> server. Use this document to reproduce the same setup in a future project.
>
> **Files:** `.claude/CLAUDE.md`, `.claude/agents/deepseek-executor.md`,
> `.claude/agents/spec-kit-coordinator.md`, `.claude/settings.json`,
> `scripts/set_deepseek_key.py`, local MCP entry in `~/.claude.json`.
>
> **Status (2026-09-13):** files created and adapted for b2b (Python scripts, no
> git); Spec Kit Claude integration installed; local MCP entry added with the
> key reused from Artemisa. `/mcp` connection and end-to-end delegation
> **NOT VERIFIED** in b2b until Claude Code is restarted and a first task is run.

## 1. Why

| Concern | Claude | DeepSeek |
|---|---|---|
| Strength | Architecture, reasoning, auditing | Cheap, fast code generation |
| Cost (per 1M tokens) | Higher | v4-flash: $0.14 in / $0.28 out · v4-pro: $0.435 in / $0.87 out |
| Role here | Specs, plans, audit, tests, applying edits | Proposes edits for one well-specified task |

Claude keeps the judgment; DeepSeek does the typing. Each delegation runs in an
isolated subagent so file-heavy context never fills Claude's main conversation.

Pricing is as reported by the MCP server's `deepseek://models` resource on
2026-09-12; check it again before relying on it.

## 2. How it works

```
User ──► Claude (main)
           │ 1. ANALYZE / 2. PLAN   (Spec Kit: spec.md → plan.md → tasks.md)
           │        └─ optional: spec-kit-coordinator subagent
           │
           │ 3. EXECUTE  ──► deepseek-executor subagent (Sonnet)
           │                   ├─ reads constitution, spec, plan, task, targets
           │                   ├─ egress check (no secrets / contact data)
           │                   └─ mcp__deepseek__deepseek_chat ──► DeepSeek API
           │                 ◄── verbatim SEARCH/REPLACE edits + usage + context sent
           │
           │ 4. AUDIT  (checklist; reject → RETRY with reason)
           │ 5. TEST   (pytest; fail → RETRY with output; cap 2 retries)
           │ 6. CONVERGE (tasks.md [x], CHANGELOG, docs)
           ▼
         Report per task: [ANALYZE] [PLAN] [EXECUTE] [AUDIT] [TEST] [FILES] [STATUS]
```

Key design choices:

- **Executor never edits files.** DeepSeek returns SEARCH/REPLACE blocks; Claude
  applies them only after the audit passes. A non-matching SEARCH block is a
  rejection, not something to hand-fix.
- **Stateless delegations.** No DeepSeek sessions; retries resend full context
  plus the previous attempt and the rejection reason.
- **Retry cap of 2**, then the user decides (re-split, `pro` model, or Claude implements).
- **Exclusions (b2b):** SMTP credentials/connection, the send path, consent and
  opt-out, contact selection rules not pinned in the plan, architecture,
  debugging → Claude only.
- **Data egress rule:** `.env*`, SMTP settings and real rows from `contactos/`
  are never sent.

## 5. Setup in a new project

### 5.1 MCP server (local scope, key never committed)

Add under `projects["<absolute project path>"].mcpServers` in `~/.claude.json`:

```json
"deepseek": {
  "type": "stdio",
  "command": "/home/<user>/.nvm/versions/node/<version>/bin/npx",
  "args": ["-y", "@arikusi/deepseek-mcp-server"],
  "env": {
    "DEEPSEEK_API_KEY": "REPLACE_WITH_DEEPSEEK_API_KEY",
    "PATH": "/home/<user>/.nvm/versions/node/<version>/bin:/usr/local/bin:/usr/bin:/bin",
    "REQUEST_TIMEOUT": "120000"
  }
}
```

If the `claude` CLI is on your PATH, the equivalent is:

```bash
claude mcp add -s local deepseek \
  -e DEEPSEEK_API_KEY=<key> \
  -e PATH="$(dirname "$(nvm which current)"):/usr/local/bin:/usr/bin:/bin" \
  -e REQUEST_TIMEOUT=120000 \
  -- "$(dirname "$(nvm which current)")/npx" -y @arikusi/deepseek-mcp-server
```

> **nvm pitfall:** nvm only adds Node to `PATH` in interactive shells. Claude
> Code launched from VS Code does not see `npx`/`node`, so a plain
> `"command": "npx"` fails silently. Always use the absolute `npx` path **and**
> set `PATH` in `env` (`npx` runs `#!/usr/bin/env node`). Update both paths when
> you switch Node versions.

Verify: restart Claude Code (or reconnect in `/mcp`) → `deepseek` shows
**connected** with tools `deepseek_chat`, `deepseek_fim`, `deepseek_sessions`.

Why not a committed `.mcp.json`? It is shared with the team, so it must not hold
the key. It supports `${DEEPSEEK_API_KEY}` expansion, but GUI-launched editors
often don't inherit shell variables. Local scope is the reliable default.

### 5.4 Install Spec Kit for Claude Code

Spec Kit ships one workflow (specify → clarify → plan → tasks → analyze →
implement → converge) that it renders per coding agent. The `claude` and
`copilot` integrations use the **same** templates, `.specify/` folder and
`specs/`; only the generated command files differ:

| Integration | Generated files | Invoke as | Setup scripts |
|---|---|---|---|
| `claude` | `.claude/skills/speckit-*/SKILL.md` | `/speckit-plan` (Claude Code) | `.specify/scripts/bash/*.sh` |
| `copilot` | `.github/agents/speckit.*.agent.md`, `.github/prompts/`, `.vscode/settings.json` | `/speckit.plan` (Copilot Chat) | per `.specify/integration.json` |

#### Step 1 — Install the `specify` CLI (once per machine)

```bash
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git
specify version        # confirm it runs
specify check          # confirm required tools (git, claude, …) are found
```

Upgrade later with `uv tool upgrade specify-cli`.

#### Step 2 — Add the Claude integration to the project

Run from the project root. **Back up first:**

```bash
tar czf ../speckit-backup-$(date +%F).tgz .claude .specify .github 2>/dev/null
specify integration status      # shows what is installed today
```

Then pick the case that matches the project:

**A. New project (no Spec Kit yet)** — b2b's case

```bash
specify init --here --integration claude --script sh
```

Add `--force` when the folder already has files (it skips the confirmation
prompt; in b2b it left existing `.claude/` files unchanged — verify with a
backup + `cmp`). Add `--ignore-agent-tools` when the `claude` CLI is not on PATH.
It does not create a git repository.

**B. Spec Kit already installed for Copilot**

```bash
specify integration install claude --force --script sh
```

- `--force` is required because the `copilot` integration is not declared
  multi-install safe. The two write to disjoint paths, so side-by-side is safe
  in practice.
- Do **not** use `specify integration switch claude` while the team still uses
  Copilot — it replaces the default integration.

**C. Claude only, and you want to add Copilot too**

```bash
specify integration install copilot --force
```

`--script sh` selects the bash setup scripts (Linux/macOS). Use `--script ps` on Windows.

#### Step 3 — Verify

```bash
specify integration status                  # "claude" listed under installed integrations
ls .claude/skills                            # speckit-analyze … speckit-tasks (10 skills)
```

`check-prerequisites.sh --paths-only` fails with "Feature directory not found"
until the first `/speckit-specify` creates `.specify/feature.json` — expected.

In Claude Code, restart the session and type `/speckit-` — the skills should be listed.

#### Step 4 — Keep it in sync

- After upgrading the CLI: `specify integration upgrade claude`.
- Never edit `.claude/skills/speckit-*` by hand; customize via Spec Kit presets
  or templates instead.
- To remove it: `specify integration uninstall claude` (keeps files you modified
  unless `--force`).

### 5.5 Project settings (`.claude/settings.json`)

```json
{
  "permissions": {
    "allow": ["Bash", "Edit", "Read", "WebFetch", "WebSearch", "Agent", "mcp__deepseek__*"],
    "deny": ["Bash(psql *DATABASE_URL_PROD*)"]
  }
}
```

- `Bash`, `Edit`, `Read` — shell commands, file edits and reads without prompts.
- `WebFetch`, `WebSearch` — documentation lookups during planning and auditing.
- `Agent` — spawning the `deepseek-executor` / `spec-kit-coordinator` subagents.
- `mcp__deepseek__*` — **all** DeepSeek MCP tools.
- `Bash(psql *DATABASE_URL_PROD*)` in `deny` — hard block on running `psql`
  against a production database. Deny rules always win over allow rules.

### 5.6 Set the API key (`scripts/set_deepseek_key.py`)

Sets `DEEPSEEK_API_KEY` on this project's local `deepseek` MCP entry, reads the
key with a hidden prompt (or from `DEEPSEEK_API_KEY`), backs up `~/.claude.json`
before writing, and can verify the key against the DeepSeek API:

```bash
python3 scripts/set_deepseek_key.py            # prompt for the key
python3 scripts/set_deepseek_key.py --check    # also verify it against DeepSeek
```

The entry must exist first (5.1). Restart Claude Code afterwards: a running
session can rewrite `~/.claude.json` and drop the change (re-run the script if
that happens).

## 6. Daily usage

Start with `/speckit-constitution` (the constitution is still the template).
Then ask Claude for work as usual. Once a spec is authorized for implementation,
Claude delegates each DEEPSEEK-classified task:

```
TASK:        T004 in specs/001-contact-import/tasks.md
TARGET:      b2b/normalize.py
CONSTRAINTS: plan §D2 column mapping; §D3 email/phone normalization rules
DONE WHEN:   normalize_email() and normalize_phone() match the §D3 table;
             tests/test_normalize.py passes with synthetic fixtures
```

Expected report:

```
[ANALYZE] no existing normalization code
[PLAN]    D2 column mapping, D3 normalization rules
[EXECUTE] Task T004 → DeepSeek v4-flash (4,210/980 tokens, $0.0009)
[AUDIT]   pass
[TEST]    pytest tests/test_normalize.py — 9 passed
[FILES]   b2b/normalize.py
[STATUS]  complete
```

## 7. Models, timeouts, cost

| Setting | Default here | Notes |
|---|---|---|
| Model | `deepseek-v4-flash` | `MODEL: pro` → `deepseek-v4-pro` for complex logic / large files |
| Thinking | off | `THINKING: on` can exceed the MCP tool timeout |
| Deprecated | `deepseek-chat`, `deepseek-reasoner` | Aliases of v4-flash; slated for removal — don't use |
| `REQUEST_TIMEOUT` (server env) | 120000 ms | Server default is 60000 |
| Claude Code MCP tool timeout | Claude Code default | Raise with the `MCP_TOOL_TIMEOUT` env var if long calls get cut |
| Cost visibility | `SHOW_COST_INFO=true` (default) | Each call returns tokens and `cost_usd`; `deepseek://usage` resource shows totals |

## 8. Security

- The API key lives only in `~/.claude.json` (local scope). Never commit it; never paste it in chat.
- b2b shares its DeepSeek key with Artemisa: rotating it means updating both
  entries (`scripts/set_deepseek_key.py` in each project).
- `~/.claude.json` should be readable only by you: `chmod 600 ~/.claude.json`.
  On this machine the home folder is on a mount that reports every file as
  `root` / `777`, so that has no effect — keep the key out of shared drives.
- DeepSeek is an external provider: prompts leave the machine. The executor's
  egress check blocks `.env` values and real client data from `contactos/`;
  credential, send-path and consent code is never delegated.

## 9. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `/mcp` shows deepseek "not connected" | `npx`/`node` not on Claude Code's PATH (nvm) | Absolute `npx` path + `PATH` in `env` (5.1) |
| Server starts but calls fail with auth error | Placeholder or revoked key | Set a valid `DEEPSEEK_API_KEY`, restart |
| Subagent says the tool doesn't exist | Wrong tool name in `tools:` | `mcp__deepseek__deepseek_chat` |
| Entry disappears from `~/.claude.json` | A running Claude Code session rewrote the file | Re-add it (5.1), then restart |
| `STATUS: TRUNCATED` | `max_tokens` too low | Re-delegate with a smaller scope or larger `max_tokens` |
| Call timeout | Thinking on / pro on huge prompt | Thinking off; raise `REQUEST_TIMEOUT` / `MCP_TOOL_TIMEOUT`; split task |
| SEARCH block doesn't apply | DeepSeek misquoted the file | Reject; re-delegate with the full current file |
| `/speckit.plan` unknown in Claude Code | Claude skills use hyphens | `/speckit-plan` (dots are the Copilot form) |
| `check-prerequisites.sh` "Feature directory not found" | No feature created yet | Run `/speckit-specify` first |
